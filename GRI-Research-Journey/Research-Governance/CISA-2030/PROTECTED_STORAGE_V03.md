# Protected Evidence Infrastructure v0.3 — implementation and deployment gate

## Completed in code
- AES-256-GCM authenticated encryption of SQLite-consistent snapshots using the optional `cryptography` Python package.
- Independent HMAC-SHA256 signing key, manifest authentication, encrypted file digest, and restored event-chain verification.
- Refusal to overwrite backup/restore targets, restrictive local permissions, and regression tests.
- No network endpoints, automated collection, or production metric changes.

## Operational limitations
- **Not deployed or provisioned**: No offsite storage, KMS, secret rotation, managed identity, encryption at rest for the live database, or scheduled backup job.
- A transient **plaintext snapshot** is created in a private temporary directory before encryption. Use an encrypted filesystem/volume for temporary storage; the module alone cannot guarantee at-rest secrecy during staging or prevent forensic recovery.
- The restore destination is plaintext SQLite. It must reside on an encrypted, access-controlled persistent volume. This module is not an encrypted live database.
- Tests require `python -m pip install cryptography`; do not change the current zero-dependency Render service to enable this experimental module.
- Keys must be generated by an approved KMS and injected separately; never commit them, log them, or store them alongside the encrypted backup.

## Existing infrastructure and next steps
The GRI Render workspace has an existing free PostgreSQL research instance; **do not repurpose it for sensitive evidence without a schema, access, persistence and retention review**. The free instance has an expiry date and is not a durable archive. The GRI dashboard is on a free Python service and does not currently mount a persistent evidence volume.

Provisioning requires a separate explicit choice of paid persistent storage, encrypted offsite destination, and credential management. Before production ingestion, implement a provider-backed identity gateway, least privilege, full evidence schema and independent artifact review, restore drills across separate infrastructure, and retention/privacy controls.

## Test
From this directory: `python -m unittest -v test_protected_backups.py`. Tests skip if the optional encryption dependency is absent; **a skipped test is not a pass**.
